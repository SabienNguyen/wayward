# Shogi Dojo

A single-page shogi (Japanese chess) game for learning: play friends online, play Claude, or play machine-learned computer opponents, with a Claude tutor, step-through strategy lessons and mating puzzles.

It is independent of the Wayward app: nothing here is imported by `src/` or built by Vite.

Published as a claude.ai artifact: <https://claude.ai/artifact/3nf9D6w3X7ACxhta4pKVVB>

## Layout

| Path | What it is |
|---|---|
| `index.html` | The built page. Generated by `build.py`; don't edit by hand. |
| `src/engine.js` | Rules engine: legal moves (drops, promotion, nifu, uchifuzume), check, alpha-beta search with quiescence. `setEval()` swaps the evaluation function. |
| `src/app.js` | Everything on the page: board UI, game modes, online lobby, Claude player, tutor, lessons, puzzles, progress. |
| `src/shell.html`, `src/*.css` | Page markup and styles, with `/*@@NAME@@*/` slots that `build.py` fills. |
| `ml/` | The learned evaluation and the scripts that train and test it. |
| `curriculum/` | Lessons and puzzles, plus the scripts that verify them. |
| `tests/` | Engine tests and Playwright browser tests (with mocked artifact capabilities). |

## Commands

Run from this directory:

```bash
python3 build.py          # rebuild index.html
bash tests/run.sh         # build + engine, lesson, puzzle and browser tests
```

Browser tests need Playwright with Chromium installed.

## How the page uses claude.ai

The page runs as a claude.ai artifact and declares three runtime capabilities. Each one is optional: when it's missing, that feature degrades and the rest of the page keeps working.

- `db`: online games live in the `games` collection. Each game document holds both seats (a viewer id or `"claude"`), the move list in USI notation, its status and its result. Every viewer replays the moves through the engine, so an illegal move can't be applied. Each player's progress is stored privately at `data/users/<id>/stats`.
- `user`: identifies seats and shows player names.
- `sample`: powers the tutor, and Claude as an opponent. Claude is given the legal moves and the engine's top candidates, and its reply is checked against the legal list. If it isn't legal, the engine's best move is played instead.

## Machine-learned opponents

`ml/ml.js` is a logistic-regression model that predicts whether the side to move goes on to win. Its features are piece counts on the board and in hand for both sides, plus piece-square features, which are heavily regularized. Each level is the same model trained on more recorded games:

```bash
node ml/gen.js 1600                    # record noisy engine games -> ml/games_*.jsonl (~40 MB, git-ignored)
PSQ_L2=0.05 node ml/fit.js 0,10,40,1328 Newborn,Novice,Apprentice,Veteran   # -> ml/final.json
node ml/match.js ml/weights.json 12 veteran:apprentice                     # head-to-head at the page's search depth
```

`ml/weights.json` holds the shipped checkpoints. Measured results, 2-ply search, 12–16 games each:

| Match | Result |
|---|---|
| Novice beat Newborn | 12–0 |
| Apprentice beat Novice | 8–4 |
| Veteran beat Apprentice | 16–0 |

A model trained on 300 games played worse than the 40-game one, so it isn't shipped. Self-play TD learning from zero was tried first and fell into a "material is bad" trap, so it was dropped. The Classic levels (hand-tuned values) are still stronger than every learned level.

## Curriculum

- `curriculum/lessons.json`: 13 lessons, each with a start position, a move line and per-move notes. `check.js` replays every line and checks the claims each lesson makes, such as castle shapes, mates and the hisshi property.
- `curriculum/puzzles.json`: 22 tsume puzzles (12 mate-in-1, 10 mate-in-3), generated with `tsume.js`. `verify_puzzles.js` independently confirms that each one is a unique-first-move mate with every attacking move a check.
